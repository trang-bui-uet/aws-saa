# AGENTS.md

## Repository overview

This repository is **not a software application** — it is an **Obsidian vault** containing personal AWS Certified Solutions Architect study notes (written mostly in Vietnamese). Content:

- Markdown notes (`*.md`) grouped by topic folders (`1. VPC`, `2. EC2`, `3. CONTAINERS & ECS`, `4. ADVANCED EC2`, `5. Route 53 - Global DNS`, `6. Relational Database Service (RDS)`).
- Images embedded via Obsidian syntax `![[Pasted image ....png]]`, stored in the repo root and in `_Attachments/`.
- `.obsidian/` holds vault config and pre-compiled community plugins (`obsidian-git`, `obsidian-vimrc-support`, `share-to-notionnext`). The plugin `main.js` files are shipped build artifacts, not source to compile.

## Cursor Cloud specific instructions

- There is **no build, test, lint, or package-manager step** in this repo: no `package.json`, `requirements.txt`, `Makefile`, `Dockerfile`, or lockfiles. Do not invent one. The update script is intentionally a no-op.
- The real "application" is the **Obsidian desktop app** (an Electron GUI) plus the `obsidian-git` plugin for versioning. Commits titled `vault backup: <timestamp>` are auto-generated by `obsidian-git`; this is the normal editing workflow. Obsidian itself cannot be meaningfully run headless in this VM.
- To preview/verify vault content in this headless environment, render the markdown to a static HTML site and view it in the browser. Note that standard markdown does not understand Obsidian's `![[embed]]` / `[[wikilink]]` syntax, so a small preprocessor is required to resolve `![[Pasted image X.png]]` (look up the basename in the repo root and `_Attachments/`) and `[[Note]]` links before conversion. `node` (with a throwaway `markdown-it`) and `python3` are pre-installed; `python3 -m venv` is unavailable and pip is externally-managed, so prefer node for tooling. This rendering is only a verification aid — keep it out of the repo and the update script.
- When editing notes, preserve the existing Obsidian embed/wikilink syntax and keep image files where the embeds expect them (repo root or `_Attachments/`).
